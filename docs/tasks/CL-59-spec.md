# CL-59 — Scope Installments and CreditCards by the current user

## Scope
Part 5 of the CL-51 split (`docs/tasks/CL-51-spec.md`, steps 5 and 6). Builds on CL-55 (`Ownership.scope/2`, `Ownership.validate_owned/3`, `cross_tenant` helper), CL-56, CL-57 and CL-58 (conventions: user-first signatures, `scope/2` on every table of a query including joins and subqueries, `{:error, :not_found}` on foreign writes, transitional `Ownership.current_user!/0` shim marked `# TRANSITIONAL: removed when CL-51 converts the caller`). After this task `Installments`, `CreditCards` and their helpers name the owner on every call and never read or change another user's rows.

In scope: `CashLens.Installments` (groups, progress, totals, projections, commitment suggestions, `find_matching_group`, `scan_and_apply_all`, `detect_and_apply`, `associate_matching_transactions`, `load_dynamic_fields`), the installment detection entry points, `CashLens.CreditCards` (statements, boletos, backfill, attach/detach, link/unlink payment, absorption, reconcile, recompute, manual statements, gaps, hub data), `CreditCards.Matcher`, `InstallmentLive.Index`, `CreditCardStatementLive.Index`, and `Api.InstallmentGroupController`.

Not in scope: `Forecast`, `Imports`, `Parsers.Ingestor`/`DirectoryImporter`, mix tasks (`--user` option), `AdminDatabaseLive`, the scoping audit test, removal of the Repo insert override / `Ownership.assign/1` / `current_user!/0`, per-user uniqueness. Those callers get only mechanical call-site updates. No UI redesign, no mock.

## Approach

### Behavior
- **Signatures.** Every public function in `Installments`, `CreditCards` and `Matcher` that touches rows takes `%CashLens.Users.User{}` first: all `list_*`, `get_*`, `create_*`, `update_*`, `delete_*`, totals/projections (`monthly_commitment`, `outstanding_balance`, `cash_flow_relief`, `monthly_projection`, `upcoming_installments`, `account_installment_*`), `suggest_commitment_patterns`, `find_matching_group`, `scan_and_apply_all`, `detect_and_apply`, `associate_matching_transactions`, `create_statement`, `create_manual_statement`, `backfill_file`, `statement_transactions`, `attachable_transactions`, `attach_transactions`, `detach_transaction`, `list_statements`, `closed_without_statement`, `get_statement_*`, `absorbed_groups`, `link_payment`, `unlink_payment`, `payment_candidates`, `unlinked_card_payments`, `suggest_payment`, `reset_account_statements`, `absorb_*`, `release_absorption`, `absorption_targets`, `reconcile_pending`, `recompute_competencia`, `list_boletos_for_account`, and `Matcher.auto_link/match_payment`. Pure functions stay unchanged (`parcel_value`, `parcel_position`, `add_months`, `last_installment_date`, `groups_due_in_month`, `total_due_in_month`, `commitment_type(s)`, `remaining_*` on in-memory groups, `change_installment_group`, `competencia_from/for`, `statement_status`, `lifecycle_status`, `pending_cycles`, `statement_gaps`, `group_by_card`, `hub_metrics`, `estimate_cycle`). `InstallmentDetector.detect/1` parses a description and touches no rows, so it stays pure; the user is passed to the `Installments` functions that call it.
- **Filtering.** Every query goes through `Ownership.scope/2` on each table (installment groups, transactions, accounts, categories, statements), joins and subqueries included. A statement of A joined to a transaction or account of B never matches. `credit_card_category_ids` lookups in `CreditCards` and `Matcher` are scoped.
- **Reads.** `get_installment_group!`, `get_statement!` and `get_statement_detail` raise `Ecto.NoResultsError` (or return nil as they do today) for another user's id; lists, totals and projections cover only the user's rows and return zero-state values for a user with no data.
- **Writes.** `update_*(user, record, attrs)` and `delete_*(user, record)` re-fetch by `record.id` through `scope/2` and return `{:error, :not_found}` for another user's row, leaving it unchanged. Statement operations given a foreign statement, payment id, transaction id or account id (`link_payment`, `unlink_payment`, `attach_transactions`, `detach_transaction`, `absorb_into`, `release_absorption`, `reset_account_statements`) return `{:error, :not_found}` and change nothing; bulk `update_all`/`delete_all` inside them are scoped. Scan/detect/reconcile/recompute operations only read and write the user's rows. Creates set `user_id` from the user; a `"user_id"` in attrs is ignored.
- **Foreign keys.** `InstallmentGroup.changeset` and `Statement.changeset` call `Ownership.validate_owned/3` for caller-supplied keys: `Statement` for `:account_id`, `:payment_transaction_id`, `:absorbed_by_statement_id`; `InstallmentGroup` for any account or category key it casts. `Transaction.changeset` additionally validates `:installment_group_id` and `:parent_id` (deferred from CL-58). A foreign id yields a changeset error on that field, not a DB error, and no row is inserted. Linking a transaction to a group inside `Installments` also verifies the group is owned.
- **Callers outside this task** (`Transactions`, `Forecast`, `Ingestor`, `DirectoryImporter`, `PdfParser`, `TransactionLive.{Index,FormComponent}`, `AccountLive.FormComponent`, `PageController`, `ImportLive`, mix tasks, `Accounts.Scopes` docs) keep compiling and passing: web callers pass `current_user`; others use `Ownership.current_user!/0` with the TRANSITIONAL marker. No behavior change there.
- **Web.** `InstallmentLive.Index` (and `index.html.heex`) and `CreditCardStatementLive.Index` use `socket.assigns.current_user` in `mount`, `handle_params`, `handle_event`, `handle_info` and async callbacks, so they show only the logged-in user's rows. Event params carrying ids (edit/delete group, attach/detach transaction, link/unlink payment, absorb, select statement) go through scoped getters; a forged foreign id gives an error flash and changes no row. A foreign group or statement id in a URL param redirects to the list route with an error flash and renders none of the data.
- **API.** `Api.InstallmentGroupController` passes `conn.assigns.current_user`; `GET/PUT/DELETE /api/installment_groups/:id` for another user's record returns `404` through the existing fallback and leaves it unchanged; `index` returns only the user's groups; `POST` with a foreign key owned by another user returns `422` with a changeset error.

### Files touched
- `lib/cash_lens/installments.ex`, `lib/cash_lens/credit_cards.ex`, `lib/cash_lens/credit_cards/matcher.ex`: user first, `scope/2` on all queries, owner on creates, `{:error, :not_found}`.
- `lib/cash_lens/installments/installment_group.ex`, `lib/cash_lens/credit_cards/statement.ex`, `lib/cash_lens/transactions/transaction.ex`: `validate_owned` on foreign keys.
- `lib/cash_lens/transactions/installment_detector.ex`: only if the compiler or docs require it; stays pure.
- `lib/cash_lens_web/live/installment_live/{index.ex,index.html.heex}`, `lib/cash_lens_web/live/credit_card_statement_live/index.ex`, `lib/cash_lens_web/controllers/api/installment_group_controller.ex`: pass the user, not-found handling.
- Mechanical call-site updates in the callers listed above and anything the compiler flags.
- Existing tests and `test/support/fixtures/credit_cards_fixtures.ex` updated to the new signatures (including `installments_scope_guard_test.exs`, `installments_apply_test.exs`, `credit_cards_backfill_test.exs`).
- New: `test/cash_lens/installments_tenancy_test.exs`, `test/cash_lens/credit_cards_tenancy_test.exs`, `test/cash_lens_web/controllers/api/installment_group_controller_tenancy_test.exs`; cases appended to `installment_live_test.exs`, `credit_card_statement_live_test.exs` and `matcher_test.exs`.

### Test criteria
- Context tenancy (via `cross_tenant`; A owns accounts, transactions, groups, statements): for B every `list_*`, total, projection, suggestion and candidate function returns `[]`/zero-state; `get_*!` raise `Ecto.NoResultsError`; `update_*`, `delete_*`, link/unlink, attach/detach and absorb return `{:error, :not_found}`; A's rows are unchanged in the DB. `scan_and_apply_all`, `reconcile_pending` and `recompute_competencia` run for B leave A's transactions and statements untouched; `Matcher` for B never links A's payment to A's statement.
- Foreign keys: B creating a group or statement with A's `payment_transaction_id`, `installment_group_id` or `account_id` gets a changeset error on that field and no row is inserted.
- API, logged in as B: `GET/PUT/DELETE /api/installment_groups/:id` for A's id returns `404` and A's row is unchanged; index lists only B's groups.
- LiveView, logged in as B: both pages list only B's rows; a foreign id in the URL or in a forged event gives a flash/redirect, shows no A data, and changes nothing.
- Full `mix test` and `mix precommit` pass.

## Expected Results
- [ ] Public functions of `Installments`, `CreditCards` and `CreditCards.Matcher` take the user first and filter every table, joins and subqueries included, through `Ownership.scope/2`; `InstallmentDetector.detect/1` stays pure and its callers pass the user.
- [ ] `installments_tenancy_test.exs` and `credit_cards_tenancy_test.exs` prove user B gets empty results, `Ecto.NoResultsError` or `{:error, :not_found}` for user A's rows and A's rows are unchanged.
- [ ] Creating an installment group or statement with a `payment_transaction_id`, `installment_group_id` or `account_id` owned by another user fails with a changeset error on that field.
- [ ] `GET/PUT/DELETE /api/installment_groups/:id` for another user's record returns `404` and leaves it unchanged.
- [ ] `InstallmentLive` and `CreditCardStatementLive` pass `current_user` into every context call and show only the logged-in user's rows.
- [ ] A foreign group or statement id in a URL or forged event gives an error flash or redirect, renders no data and changes no row.

## Out of Scope
- Forecast, Imports, Ingestor, DirectoryImporter, mix tasks, `AdminDatabaseLive` (later CL-51 parts).
- Removing the Repo override, `Ownership.assign/1`, `current_user!/0`; the scoping audit test.
- Per-user uniqueness constraints.
